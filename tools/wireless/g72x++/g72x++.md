# g72x++

> Decoder that turns raw ITU G.726/G.721/G.723 ADPCM voice streams into playable audio.

## What it's for

g72x++ (Arne Bochem, ps-auxw.de) extends Sun Microsystems' public-domain CCITT G.711/G.721/G.723 reference code with a standalone G.726 decoder taken from Steve Underwood's spandsp. The packaged program, `decode-g72x`, reads a raw ADPCM byte stream on standard input and writes decoded audio to standard output — there are no file headers, no containers, and no capture-file parsing, so it is meant for the raw codec payloads you extracted elsewhere (e.g. a voice channel pulled out of a telephony capture). Use it to make such intercepts audible or feedable to other audio tools; the distro package ships the decoder only, and it neither captures nor demultiplexes traffic itself.

## Typical use cases

### Decode a raw G.726 32 kbps capture to linear PCM

Make the most common ADPCM variant playable.

```
decode-g72x -64 -l < capture.raw > out.pcm
```

Outcome: reads the raw G.726 32 kbps stream from stdin and writes 16-bit linear PCM to out.pcm, ready for playback or import as raw audio; `-62`, `-63` and `-65` select the 16, 24 and 40 kbps G.726 rates instead.

### Decode classic CCITT G.721/G.723 streams to u-law

Handle the older Sun-style ADPCM variants with the same tool.

```
decode-g72x -4 < capture.raw > out.ulaw
```

Outcome: decodes G.721 32 kbps (4-bit) data to 8-bit u-law audio on stdout; `-3` and `-5` select the G.723 24 kbps and 40 kbps variants, and `-a` switches the output to A-law.

### Decode right-packed G.726 samples

Handle captures whose ADPCM bits are packed the other way around.

```
decode-g72x -64 -R -l < capture.raw > out.pcm
```

Outcome: interprets the bitstream as right-packed instead of the default left-packed (`-L`) or unpacked (`-n`), producing clean audio where the default mode would yield garble.
