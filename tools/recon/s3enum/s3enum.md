# s3enum

> Stealthy Amazon S3 bucket enumeration over DNS — bucket discovery that never touches S3 access logs.

## What it's for

s3enum finds existing S3 buckets belonging to a target by resolving candidate bucket names instead of sending HTTP requests: because it queries DNS only, the enumeration leaves no trace in the target's S3 server access logs. Candidate names are generated by combining a base name with every wordlist entry (joined with `-`, `_`, `.` or nothing), optionally prefixed/suffixed from a suffix list, then resolved under the S3 naming space where existing buckets answer with a CNAME. Written in Go. Known limitation: buckets in the us-east-1 region resolve to a CNAME indistinguishable from a nonexistent bucket and are missed.

## Typical use cases

### Enumerate buckets derived from one base name

Discover bucket names built around a target's name.

```
s3enum -wordlist wordlist.txt -suffixlist suffixlist.txt examplecorp
```

Outcome: prints every candidate name that resolves to an existing bucket (e.g. examplecorp-attachments, examplecorp-static); silence for a name means it does not resolve.

### Tune resolver, speed and check several base names

```
s3enum -wordlist wordlist.txt -suffixlist suffixlist.txt -nameserver 1.1.1.1 -workers 100 examplecorp examplecorp-staging examplecorp-backup
```

Outcome: resolves through the chosen name server instead of /etc/resolv.conf, raises parallelism to 100 workers, and sweeps multiple base names in one run.
