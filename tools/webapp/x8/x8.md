# x8

> Hidden parameter and header discovery suite that diffs responses to find undocumented inputs.

## What it's for

x8 brute-forces parameter names against a target URL and reports which ones actually exist, by comparing responses line by line, watching response codes, and tracking reflections — a more accurate signal than naive reflection checks, and capable of finding parameters whose values are not random (e.g. `admin=true`). It works on GET queries, POST bodies (including JSON via a `%s` injection template), raw request files, HTTP headers, and even individual header values, can check thousands of URLs in one run, and can replay every discovered parameter through a proxy such as Burp. It is an attack-surface discovery tool (a fast, scriptable counterpart to Burp Param Miner), not a vulnerability scanner; it does not test the parameters it finds. Written in Rust.

## Typical use cases

### Discover hidden query parameters

Fuzz the query string of a single endpoint with a wordlist of parameter names.

```
x8 -u "https://example.com/" -w params.txt
```

Outcome: x8 sends learn requests, then batches candidate parameters into probe requests; existing parameters are listed on screen and written to the output file, while non-existent ones produce no page difference. Adding an existing parameter to the URL (e.g. `https://example.com/?something=1`) makes x8 append candidates alongside it.

### Fuzz parameters inside a JSON body

Probe a POST endpoint whose parameters live in a JSON structure, using `%s` as the injection point.

```
x8 -u "https://example.com/" -X POST -b '{"x":{%s}}' -w params.txt
```

Outcome: each probe becomes `{"x":{"a":"b3a1a","b":"ce03a",...}}` posted to the target, and parameters that change the response are reported — useful for undocumented JSON API fields.

### Discover hidden HTTP headers

Switch from parameter mode to header-discovery mode.

```
x8 -u "https://example.com" --headers -w headers.txt
```

Outcome: wordlist entries are sent as HTTP headers instead of parameters (Content-Length and Host are excluded automatically), and headers the server recognizes are reported.

### Fuzz a single header's values

Test candidate values for one specific header by marking the injection point inside it.

```
x8 -u "https://example.com" --headers -H "Cookie: %s" -w values.txt
```

Outcome: every wordlist entry is substituted into the Cookie header; values that alter the response (for example an internal role cookie name) are flagged in the output.

### Force a non-standard parameter syntax

Use a parameter template for endpoints that expect array-style or prefixed parameters.

```
x8 -u "https://example.com/" --param-template "user[%k]=%v" -w params.txt
```

Outcome: probes are sent as `/?user[a]=hg2s4&user[b]=a34fa&...` instead of the default `key=value` form, matching applications that parse nested or namespaced input.

### Scan many URLs in parallel

Hand x8 multiple targets and let it check them concurrently.

```
x8 -u "https://example.com/" "https://target.example.com/" -W0
```

Outcome: with `-W0` all URLs run in parallel and each URL's discovered parameters are reported separately, making a one-pass sweep across a list of endpoints. A raw request can also be used instead of a URL via `-r request.txt`.
