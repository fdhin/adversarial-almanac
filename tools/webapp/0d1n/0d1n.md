# 0d1n

> Web attack automation in C — threaded request driver for brute-forcing logins, discovering paths and probing for SQLi/XSS/SSRF/command injection, with HTML report generation.

*No corpus evidence — derived from upstream documentation (the upstream repository has since been removed from GitHub; the archived README is the source).*

## What it's for

Replaying a wordlist of payloads against a URL template at high concurrency and recording what comes back. A caret (`^`) in the target URL or POST body marks where each payload is inserted, which is what lets it drive path discovery, credential stuffing and injection probing with the same mechanics. Built-in extras matter in practice: it can reload an anti-CSRF token for every request, rotate a random proxy or user agent per request, tamper payload case to slip past naive WAF rules, and run a slowloris-style keep-alive test. Results land in an HTML report you can serve with `0d1n_view`. It is a driver, not a scanner with a vulnerability database — you choose the payload lists and the success criteria.

## Typical use cases

### Brute-force directories by status code

```
0d1n --host http://target.example.com/^ --payloads /opt/0d1n/payloads/dir_brute.txt --threads 500 --timeout 3 --log run1 --save_response
```

Outcome: every path in the wordlist is requested with the caret as the insertion point; the run log (`--log run1`) collects which paths returned interesting status codes, and `--save_response` stores the response bodies so they can be reviewed in the HTML report afterwards. Thread counts in the hundreds are fine on modest hardware; tune up if the target keeps up.

### Probe a parameter for SQL injection

```
0d1n --host 'http://target.example.com/view/1^/product/^/' --payloads /opt/0d1n/payloads/sqli_list.txt --find_string_list /opt/0d1n/payloads/sqli_str2find_list.txt --log run2 --tamper randcase --threads 800 --timeout 3 --save_response
```

Outcome: each payload is injected at both carets; responses are matched against the strings in `--find_string_list` (error messages, SQL fragments) to flag likely injections. `--tamper randcase` randomizes the payload's letter case per request, a cheap evasion against case-sensitive WAF rules.

### Brute-force a login form

```
0d1n --host 'http://target.example.com/auth.py' --post 'user=admin&password=^' --payloads /opt/0d1n/payloads/wordlist.txt --log run3 --threads 500 --timeout 3
```

Outcome: the password field (caret position) is filled from the wordlist while the rest of the POST body stays fixed; successful logins stand out in the run log by response size or redirected content. If the form uses an anti-CSRF token, 0d1n can be told to fetch a fresh token for every request so the attempts are not rejected outright.
