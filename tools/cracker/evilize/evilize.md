# evilize

> Builds two executables with identical MD5 hashes but different (good/evil) behavior, from a single program linked against goodevil.o.

*No corpus evidence — derived from upstream documentation.*

## What it's for

evilize (Peter Selinger, 2006; distributed from his MD5-collision page, GPL) is a research tool for demonstrating why MD5 must not be used to vouch for binaries. You write one C program with two top-level functions `main_good()` and `main_evil()` and link it against the shipped `goodevil.o`; evilize then splices in MD5 collision blocks (generated by Patrick Stach's `md5coll` engine, implementing Wang et al.'s attack) so the resulting `good` and `evil` files hash identically while behaving differently — the classic attack on binary-signature or integrity-check schemes that rely on MD5. It produces demo pairs for a program you compile yourself; it cannot retro-collide two arbitrary existing binaries. The collision generation step is slow (hours).

GitHub: third-party mirror of Peter Selinger's evilize tarball (mathstat.dal.ca).

## Typical use cases

### Get the initial vector for a template program

First step after compiling `hello-erase.c` (the shipped example) with `gcc hello-erase.c goodevil.o -o hello-erase`.

```
evilize hello-erase -i
```

Outcome: prints the program's near-collision initial vector as four hex words — these become the arguments to the collision generator in the next step. Templates must use `main_good()`/`main_evil()` instead of `main()`.

### Generate the MD5 collision blocks

Feed the vector to the collision engine (installed as `evilize-md5coll`; upstream source name `md5coll`).

```
evilize-md5coll 0x23d3e487 0x3e3ea619 0xc7bdd6fa 0x2d0271e7 > init.txt
```

Outcome: after several hours of computation, writes the precomputed collision blocks to `init.txt`. Doing this as a separate step is the recommended workflow precisely because it is the expensive part and the result is reusable with `-c`.

### Build the good/evil pair from a precomputed collision

Assemble the two colliding binaries.

```
evilize hello-erase -c init.txt -g good -e evil
```

Outcome: writes `good` and `evil`. `md5sum good evil` prints the same digest for both, while running them triggers `main_good()` and `main_evil()` respectively — the demonstration payload.

### One-shot pair generation

Skip the manual two-step when you don't need to reuse the collision.

```
evilize hello-erase -g good -e evil
```

Outcome: computes the initial vector and collision inline and writes the finished `good`/`evil` pair directly — same result as the `-i` → `md5coll` → `-c` chain, just without a saved `init.txt`. `-s <n>` pins the random seed for reproducible runs.
