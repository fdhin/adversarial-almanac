# z3

> Microsoft Research's SMT theorem prover: state constraints over integers, bitvectors and strings, and let it find the satisfying input.

## What it's for

Z3 is the standard constraint solver behind program-analysis, verification
and — on the offensive side — keygenning and crackme solving. You describe
a problem as logical constraints (arithmetic over ints/reals, fixed-width
bitvector operations, arrays, strings) and Z3 either proves them
unsatisfiable or produces a concrete model: the exact values that satisfy
them. Typical attack uses are inverting a serial-check routine whose
conditions you have reversed, recovering inputs that produce a target hash
or checksum, and solving symbolic-execution queries emitted by tools like
angr (which embed Z3 as its solver). It is consumed as a CLI reading
SMT-LIB2 files or through bindings for Python (`z3-solver`), C/C++, Java,
.NET, OCaml and more; it is a solver engine, not a scanner — you bring the
constraints.

## Typical use cases

### Solve an SMT-LIB2 constraint file

Feed the standard input format straight to the binary.

```
z3 constraints.smt2
```

Outcome: reads the SMT-LIB2 declarations/assertions and prints `sat`/
`unsat`/`unknown`, followed by the satisfying assignment (`get-model`
output) when one exists — the zero-setup way to check a constraint set
saved from a solver front-end.

### First solve from Python

Install the bindings and run the upstream example shape.

```
pip install z3-solver
python3 -c "from z3 import *; x = Real('x'); y = Real('y'); s = Solver(); s.add(x + y > 5, x > 1, y > 1); print(s.check()); print(s.model())"
```

Outcome: prints `sat` and a model assigning `x` and `y` concrete values
that meet all three constraints — the canonical `Solver()/add()/check()/
model()` cycle that every Z3 script follows.

### Invert a serial check (keygenning)

Turn reversed check conditions into a solvable system.

```
python3 keygen.py
```

```python
# keygen.py
from z3 import *
name_len = 8
serial = [Int(f"c{i}") for i in range(name_len)]
s = Solver()
s.add([c >= 0x20, c <= 0x7e for c in serial])            # printable
s.add(serial[0] + serial[1] == 0xC1)                     # reversed checks
s.add(serial[2] ^ serial[3] == 0x37)
s.add(sum(serial) % 256 == 0x4D)
print(s.check())
print("".join(chr(s.model()[c].as_long()) for c in serial))
```

Outcome: `sat` plus one valid serial satisfying every condition lifted
from the target's validation routine — re-run with an extra `s.add(...)`
exclusion to enumerate alternatives.

### Solve over raw machine word semantics

Model integer overflow and bit tricks exactly.

```
python3 -c "from z3 import *; x = BitVec('x', 32); s = Solver(); s.add(x * x == 0x12345678); print(s.check(), s.model())"
```

Outcome: searches 32-bit values whose squared product wraps to the target
constant — bitvector math wraps modulo 2^N exactly like the CPU, which is
why Z3 is the backend symbolic executors use for path constraints.

### Check solver version in use

Confirm which Z3 a script/toolchain embeds.

```
python3 -c "import z3; print(z3.get_version_string())"
```

Outcome: prints the wrapped libz3's version string — useful when a tool
(angr, Manticore) pins its own solver and solver behavior differs from
your system `z3` binary.
