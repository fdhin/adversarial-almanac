# k55

> Minimal C++ ptrace utility that injects a 27-byte `/bin/sh` shellcode into a running x86_64 Linux process by name.

## What it's for

k55 does one thing: given a process name, it attaches with `ptrace()`, writes a hardcoded 27-byte execve(`/bin/sh`) payload into the target's address space, and redirects execution there — spawning a shell that lives inside the victim process, inheriting its privileges. The payload is fixed (a shell-storm-derived `execve` stub); you cannot supply your own shellcode. The target must have an `r-xp`/`execstack`-style writable-executable route or the injected bytes cannot run, so hardened binaries (and anything that blocks ptrace, like Yama restrictions) are out of scope. It is a teaching-grade demonstration of Linux process infection — useful in labs to show live-process shell injection, not a stealth tool: `PTRACE_POKETEXT` activity is plainly visible.

*No corpus evidence — derived from upstream documentation.*

## Typical use cases

### Inject a shell into a running process by name

Spawn a shell inside an already-running target process.

```
sudo ./K55 k55_test_process
```

Outcome: k55 attaches to every process named `k55_test_process`, writes the shellcode, and a `/bin/sh` prompt appears running inside the target's address space with the target's user context; run it as root to attach to arbitrary processes.

### Practice against the bundled test process

Use the shipped dummy target to rehearse before touching a real one.

```
./k55_example_process/k55_test_process
sudo ./K55 k55_test_process
```

Outcome: terminal one runs the harmless test process; the injection in terminal two spawns a shell inside it — a safe end-to-end check that the injector and ptrace permissions work on your system.

### Mark a target binary executable-stack before injecting

Give the payload an executable region to land in when the binary lacks one.

```
sudo execstack -s /usr/bin/gdb
```

Outcome: the ELF is flagged to map an executable stack, so k55's injected bytes can execute inside it; without this (or an existing `r-xp` route) the injected shellcode segfaults instead of running.
