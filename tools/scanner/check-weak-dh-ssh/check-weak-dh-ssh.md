# check-weak-dh-ssh

> Offline checker that finds SSH clients affected by the 2006-2008 Debian OpenSSL predictable-key bug, from a packet capture.

## What it's for

check-weak-dh-ssh (check_weak_dh_ssh.pl, v0.1, Alexander Klink / Cynops GmbH, released at EuSecWest 2008) examines a pcap capture of SSH traffic and reports which client hosts used Diffie-Hellman key-exchange values generated by Debian's broken OpenSSL PRNG (CVE-2008-0166). It works entirely offline: it walks the capture's SSH key-exchange messages, checks the DH values against the precomputed set of keys that the vulnerable PRNG can produce (bundled with the script; the first-run expansion is cached to disk), and prints per-connection verdicts plus vulnerable/invulnerable client summaries. It never contacts the hosts, so coverage is only as good as the capture. It detects vulnerable clients only — it is not a general SSH or DH auditor.

No corpus evidence — derived from the upstream source.

## Typical use cases

### Analyze a capture for vulnerable SSH clients

Process a pcap of port-22 traffic and list weak clients.

```
check-weak-dh-ssh ssh-traffic.pcap
```

Outcome: each SSH key-exchange frame is printed with its endpoints and message code, followed by lists of vulnerable and invulnerable client hosts — clients whose DH exchange matches Debian-PRNG output are flagged.

### Reuse the key-expansion cache

Skip the lengthy first-run key expansion by pointing at a stored cache.

```
check-weak-dh-ssh -c check_weak_dh_ssh.cache --filter "tcp port 22" ssh-traffic.pcap
```

Outcome: the precomputed key cache is loaded from the named file instead of being rebuilt, and only frames matching the BPF filter are parsed; use `--no-cache` to force a full rebuild.

### Quiet, DNS-free triage

Run without per-frame chatter or reverse lookups.

```
check-weak-dh-ssh -q -n ssh-traffic.pcap
```

Outcome: per-frame output is suppressed and no DNS resolution of captured addresses is attempted; only the final vulnerable/invulnerable summaries are printed.
